# Project Memory

_Facts, conventions, and patterns discovered about this project._

---

## Architecture

- **Homepage:** 13-section vertical scroll with ScrollReveal wrappers. HomePage.tsx assembles: HeroCarousel → CounterBar → WelcomeSection → WhySection → ProgramsGrid → HolisticSection → GallerySection → CampusThenNow → AchievementsSection → StudentLifeSection → TestimonialsSection → AdmissionsCTA → EventsPreview → NewsSection → LocateSection. Each section is a self-contained component with its own CSS module.
- **IA:** 6 top-level sections: About Us (7 subpages), Academics (7 subpages), Admissions (3 subpages), Beyond Academics (5 subpages), News & Media (4 subpages), Contact Us (4 subpages). 46 routes total.
- **Page template:** Every page uses `createPageMetadata` for SEO meta, `getHeroImage("section-name")` for hero images. Pages use either `ContentPage` template or custom `PageShell + Hero`.
- **Data layer:** All content is static, sourced from `@/data/*` modules. No CMS, no API, no runtime fetching. One data file per content domain.
- **MenuOverlay:** React Context (MenuProvider) shares `isOpen`/`toggle`/`close`/`triggerButtonRef` between Header and MenuOverlay. MenuOverlay renders once in root layout. Header falls back to legacy props when context is absent.
- **All overlays/dialogs MUST implement:** useFocusTrap, lockBodyScroll, aria-modal, Escape close, focus restoration. MenuOverlay.tsx is the reference implementation.
- **Every route group** must have its own `error.tsx` boundary.
- **Suspense boundaries:** Required around `useSearchParams`, `cookies()`, and dynamic APIs. Applies to homepage and layout search providers.

## Design System

- **CSS Modules** throughout. No Tailwind, no styled-components, no CSS-in-JS.
- **Three-tier tokens:** primitives (`--p-*`), semantics (`--s-*`), component (`--c-*`). Primitives defined ONLY in `globals.css`.
- **Responsive:** Three breakpoints: 420px, 760px, 1100px. Container queries (@container) for component-level responsiveness.
- **Animation:** motion/react (`motion`, `AnimatePresence`) for declarative animations. ScrollReveal uses IntersectionObserver + CSS transitions for SSR-safe scroll reveals. All animations respect `prefers-reduced-motion`.

## Testing

- **Vitest** for unit tests, **Playwright** for E2E with chromium/firefox/webkit.
- `@axe-core/playwright` for a11y audit gates.
- Coverage thresholds: 80% statements, 75% branches, 80% functions/lines.

## Security

- **JSON-LD XSS:** Always use `safeJsonStringify()` from `@/lib/safe-json` — escapes `<` → `\u003c` and `>` → `\u003e` to prevent `</script>` injection in JSON-LD blocks. Based on OWASP + Redux security guidance.
- **CSP:** Enforced via middleware. `script-src 'self'`, no nonce needed for static site. `style-src 'self' 'unsafe-inline'` for CSS Modules.
- **Contact form:** Layered bot defense: honeypot → timing check → rate limit → email. Honeypot silently returns success. `serverActions.bodySizeLimit: "100kb"`.
- **Security headers:** HSTS with `max-age=63072000; preload`, COOP/ CORP: `same-origin`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`.
- **No secrets** in source code. `RESEND_API_KEY` accessed via `process.env` in server actions only.

## Conventions

- **Custom Link** primitive (not raw `next/link`) for all links — centralizes external detection, variant styling, and `ariaDisabled`.
- **Contact form** uses `useActionState` + colocated `actions.ts` Server Action pattern. Unique IDs via `useId()` for label-input associations.
- **Async search** MUST use `cancelled` flag pattern — `clearTimeout` only cancels the timer, not in-flight async operations.
- **Skip-link targets** MUST have visible focus indicators (no `outline: none`). WCAG 2.4.7.
- **Carousel dots** use `role="group"` + `aria-current` (not conflicting `tablist` pattern). Autoplay requires visible pause button (WCAG 2.2.2).
- **Breadcrumbs** wrap in `<ol>` for semantic structure.
- **Contact form** fields use `autocomplete="name"`, `"email"`, `"tel"`.
- **`useFocusTrap`** visibility check uses `getComputedStyle` + `offsetWidth/Height` (handles `position:fixed` elements).
- **`scroll-lock.ts`** has SSR guard: `typeof document === "undefined"` early return.
- **Image optimization:** `sizes` attributes tuned to actual CSS layout, not generic values. Priority images use `priority` on first slide only.

## Emails

- **@react-email/components** for HTML templates rendered via `render()` and sent through Resend. JSX interpolation auto-escapes — no `dangerouslySetInnerHTML` in email templates.
- **Architecture:** Next.js 16 App Router uses reactStrictMode: true by default — all client components must be StrictMode-safe. Never use useRef guards (didInit, hasMounted) to gate one-shot effects; use useState initializers or reset the ref in the cleanup function instead. _(Rationale: React StrictMode simulates unmount/remount in dev, and useRef values persist across this cycle. A didInit guard blocks the second mount after the first mount's cleanup kills the effect's setup (e.g., clears a setTimeout). This causes permanent deadlock visible only in dev.)_ — 2026-07-06
- **Architecture:** Do not wrap statically renderable server components in Suspense unless they actually suspend (async data fetching, dynamic imports, etc.). React 19.2's progressiveChunkSize (default 12,800 bytes) renders the fallback for Suspense boundaries whose children exceed this size, causing SSR to omit content. _(Rationale: React 19.2 introduced outlining: Suspense boundaries with children >12,800 bytes render the fallback during the initial SSR stream as an optimization. For large server components that never suspend (like HomePage with 14 sections), this causes the entire page body to render as null on SSR.)_ — 2026-07-06
- **Accessibility:** Never use opacity-based scroll reveal animations. Use transform-only (translateX/Y) so content defaults to opacity: 1 (CSS default). Content must be visible on first paint regardless of SSR state, hydration timing, reduced-motion preference, or animation library bugs. _(Rationale: Opacity-driven scroll reveals fail in three independent failure modes: SSR (content invisible until hydration), prefers-reduced-motion (transitions disabled → content stays at opacity: 0 permanently, a WCAG 2.3.3 violation), and library bugs (motion's whileInView may never fire on modern Next.js + Turbopack stacks). Transform-only reveals degrade gracefully: content is always visible, transforms are simply skipped when animation is unavailable.)_ — 2026-07-06
- **Architecture:** motion library (formerly framer-motion) whileInView has known reliability issues on Next.js 16 + Turbopack stacks. Design animations to be resilient to whileInView never firing — content must be visible in the initial state. _(Rationale: motion@12.42.2 has an open bug (issue #3565) where whileInView intermittently does not fire on Next.js 16 with Turbopack, leaving elements stuck at their initial state. This means opacity-based scroll reveals are fundamentally unreliable on this stack regardless of correct code.)_ — 2026-07-06
- **Testing:** Target 70%+ test coverage with unit tests (Vitest) for utilities, components, hooks, and server actions, plus E2E tests (Playwright) for critical user journeys _(Rationale: Critical business logic like contact form submission must be tested to prevent silent failures in production. Test coverage was initially at ~5%, now targeting 70%.)_ — 2026-07-10
- **Configuration:** All hardcoded values must live in src/shared/config.ts with environment variable overrides, not scattered across 42+ files _(Rationale: Magic numbers and hardcoded values (founding year, enrollment stats, z-indexes, animation durations) were scattered everywhere. Centralized config enables environment-specific overrides and eliminates maintenance overhead.)_ — 2026-07-10
- **Security:** Never use static CSP nonces in .env files. Generate nonces dynamically in middleware using crypto.randomUUID() per Next.js documentation _(Rationale: Static CSP nonces in environment variables provide zero security and expose the app to XSS. CSP nonces must be unique per request, generated in middleware.)_ — 2026-07-10
- **Error Handling:** Integrate error monitoring (Sentry) for production. Wrap external library components in error boundaries to prevent cascade failures _(Rationale: Production errors were only logged to console with no monitoring, making it impossible to detect and debug issues reported by users.)_ — 2026-07-10
- **Performance:** Avoid heavy decorative libraries. Use CSS-only effects where possible, and lazy load heavy components with dynamic imports only when truly needed _(Rationale: Heavy 3D libraries (Spline, Globe, tsParticles, ZProximityEngine) totaling 850KB+ were loaded for decorative effects, killing mobile performance and Core Web Vitals.)_ — 2026-07-10
- **Async Patterns:** Use AbortController instead of boolean flags for cancelling async operations in useEffect cleanup functions _(Rationale: Using boolean `cancelled` flags for async cleanup creates race conditions where cleanup happens after the check but before setState. AbortController is the standard browser API for reliable cancellation.)_ — 2026-07-10
- **SEO:** Use combined School + EducationalOrganization + LocalBusiness schema types with full contact info, opening hours, and geo coordinates for maximum SEO value _(Rationale: Schema.org School type alone is insufficient for local search. LocalBusiness schema with opening hours, geo coordinates, and area served improves local SEO and Google Maps visibility.)_ — 2026-07-10
- **Component Constraints:** Text and Heading components do NOT accept style prop. For custom styling, wrap with p, div, or span elements using inline styles referencing CSS custom properties (var(--p-color-_), var(--p-space-_), var(--p-font-size-\*)). _(Rationale: The domain UI components (Text, Heading, Card) accept only className and their defined props — not arbitrary style. This ensures consistent design system usage. Found across multiple pages (contact, news, staff, curriculum).)_ — 2026-07-12
- **Architecture:** `shared/lib/brand.ts` is the single source of truth for domain, email, social links, and school identity. `config.ts` MUST import its defaults from brand.ts — never hardcode. If the school rebrands, only brand.ts needs updating. _(Rationale: config.ts had hardcoded email (st.elizabethgoa@gmail.com) and empty social links that diverged from brand.ts's actual values (info@stelizabethhighschool.in, real Facebook/Instagram URLs). This caused structured data to use the wrong email and breadcrumb schemas to point at the wrong domain (stelizabeths.in).)_ — 2026-07-12
- **Convention:** Every content page with a visual `<Breadcrumb>` widget MUST also render `<BreadcrumbJsonLd>` with matching items. BreadcrumbList is the highest-impact structured-data type for Google SERP breadcrumb paths. _(Rationale: 22 pages had visual breadcrumbs but only 7 had JSON-LD. Google uses BreadcrumbList to display the breadcrumb path in search results — without it, SERP entries show flat URLs instead of hierarchical paths.)_ — 2026-07-12
- **Architecture:** Hero videos MUST be dual-format (MP4/WebM via `<source>`), compressed below 10MB, have a poster frame, respect prefers-reduced-motion, and use `faststart` for MP4 progressive loading. Git-ignore raw video files. _(Rationale: The original 137MB/93s/12Mbps video was unusable for web. Compressed to 5.3MB/25s/1.8Mbps H.264 + 5.9MB WebM. Added poster frame at 3s mark, reduced-motion respect, and dual-format negotiation via `<source>` elements.)_ — 2026-07-12
- **Architecture:** All structured-data generators in `enhanced-structured-data.ts` MUST use `absoluteUrl()` from brand.ts for canonical URLs — never hardcoded strings. Same for `createBreadcrumbSchema`, `createWebSiteSchema`, and identical in `structured-data.ts`. _(Rationale: `enhanced-structured-data.ts` had 12 hardcoded `https://stelizabethhighschool.in` URLs. `seo.ts` used the WRONG domain `https://stelizabeths.in`. Both now route through `absoluteUrl()` or `SITE_URL` from brand.ts.)_ — 2026-07-12
- **Security:** Gate all client-side `console.error` and `console.warn` behind `process.env.NODE_ENV === "development"`. Server-side logging is acceptable. _(Rationale: Client-side console.error() calls in error boundaries and feature components leak internal error details in production. All client-side console.error/warn calls must be gated behind `process.env.NODE_ENV === "development"`. Server-side console.error in actions.ts is acceptable for monitoring/auditing.)_ — 2026-07-12
- **Architecture:** Structured data: use `structured-data.ts` for page-level schemas (WebPage, Breadcrumb, FAQ, NewsArticle); use `enhanced-structured-data.ts` only for layout-level schemas (School, WebSite, Event, Person, Review). Never add a third structured-data file. _(Rationale: All structured data generation lives in `structured-data.ts` (WebPage, NewsArticle, FAQ, Breadcrumb, Organization). `enhanced-structured-data.ts` exists for layout-level schemas (School, WebSite, Event) used in root layout and events-calendar. The `seo.ts` file (previously a third duplicate) has been consolidated. Future schema additions should go to `structured-data.ts` unless they require the richer shapes in `enhanced-structured-data.ts`.)_ — 2026-07-12
- **Convention:** App pages and screens import from `@/shared/lib`; data/config/lib-internal files may import from `@/shared/lib/brand` directly. _(Rationale: App-level pages and screens should import from `@/shared/lib` (the barrel/public API). Only data files (`*.data.ts`), config files, and shared/lib internals should import directly from `@/shared/lib/brand`. - **Pattern:** Site-wide fixed banners must set `--announcement-height` via ResizeObserver on `<html>`. All fixed elements (Header, progress bars) must offset their `top` by `var(--announcement-height, 0px)`. `#main-content { scroll-padding-top }` must include `var(--announcement-height, 0px)`. _(Rationale: When a site-wide banner (announcement bar) is positioned fixed at top, all other fixed elements (Header, ReadingProgressBar) must offset by its height. Use a CSS custom property (`--announcement-height`) set via ResizeObserver so the offset stays accurate across text wrapping and viewport changes. This avoids manual height calculation and works across all layouts. Scroll-padding-top in globals.css must also include the announcement height.)_ — 2026-07-12
- **Architecture:** Admin CMS architecture: /admin/_ routes with server-side auth checks, service-role Supabase client for CRUD, per-table repository modules with Zod validation, static .data.ts fallback when SUPABASE*URL is unset. No route groups for admin — must use a real path segment. *(Rationale: Admin panel uses real /admin/_ routes (not a route group) to avoid path collisions with (site) and (home). The admin layout uses server-side Supabase auth checks (getUser() + role metadata). The service-role Supabase client (server-only) bypasses RLS for admin CRUD. Repository modules (news.repository.ts, etc.) isolate all database access behind typed CRUD functions with Zod validation. The static .data.ts files remain as compile-time fallback — no behavioral change without SUPABASE*URL set.)* — 2026-07-12
- **Tooling:** Supabase client pattern: browser (anon key, client.ts), server (anon key + cookies via @supabase/ssr, server.ts), admin (service*role key, server-only, admin.ts). CSP must allow connect-src to Supabase domain. `cacheComponents: true` incompatible with dynamic admin routes. *(Rationale: The `@supabase/ssr` package's createServerClient requires `cookies()` from next/headers. Three client types: browser (public anon key, for client components), server (anon key + cookies, for RSCs and middleware), admin (service*role key, server-only, bypasses RLS). The admin client must never touch browser code — enforced by `import "server-only"`. CSP middleware must allow connect-src to the Supabase REST API domain. `cacheComponents: true` in next.config.ts conflicts with dynamic admin pages — removed.)* — 2026-07-12
- **Architecture:** Per-section admin auth: each /admin/(authenticated)/{section} has its own layout.tsx calling requireSection(section). Roles: super*admin, news_editor, announcement_editor, event_editor, alumni_editor, gallery_editor. Auth module split into client-safe auth-types.ts and server-only auth.ts. Route group (authenticated) provides transparent auth gate; per-section layouts add chrome and role enforcement. *(Rationale: Each content section (news, announcements, events, alumni, gallery) gets an independent role (news*editor, announcement_editor, etc.) plus a super_admin who sees everything. The auth module is split into client-safe auth-types.ts (pure type definitions, role enums, labels, canAccessSectionByRole function) and server-only auth.ts (Supabase-dependent guards: requireSection(), requireAnyAdmin(), getRole()). This prevents server-only imports from leaking into client components like LoginForm. Each /admin/(authenticated)/{section}/layout.tsx independently calls requireSection(section) — so a news_editor who types /admin/alumni gets redirected to /admin/news. The transparent route-group layout at (authenticated)/layout.tsx only calls requireAnyAdmin() — minimal gate, chrome-free.)* — 2026-07-12
- **Architecture:** Supabase data bridge pattern: _.fetcher.ts modules use `await import()` with try/catch to bridge Supabase repositories to public pages. Static .data.ts remains the fallback. Check `process.env.NEXT_PUBLIC_SUPABASE_URL` once (cached). No page should import .data.ts directly anymore — use the .fetcher.ts instead. \_(Rationale: Each content type has a _.fetcher.ts bridge module that uses dynamic import() of the repository in try/catch. If SUPABASE*URL is unset, it returns static .data.ts exports immediately (zero overhead). If configured, it attempts the fetch and falls back if the query returns empty or fails. - **Architecture:** Async RSC bridge pattern: All public-facing pages should consume data through \*.fetcher.ts bridge modules that dynamically try Supabase repositories first, fall back to static .data.ts files. - **Architecture:** Every barrel export (index.ts re-export) must have at least 1 consumer outside the barrel's own test files. Verify with: grep -rl "ExportName" src/ --include='_.tsx' --include='_.ts' | grep -v **tests** | grep -v index.ts. If no results, delete the export and its test. _(Rationale: Dead barrel exports bloat the public API surface and confuse future developers. AspectRatio, Badge, SchoolCursor, and VisuallyHidden all passed typecheck but had 0 production consumers — all cleaned in this audit.)_ — 2026-07-12
- **Testing:** Zod validation chain order determines error priority. .email("msg") catches empty strings before .min(1, "msg") — tests must assert the Zod-order error, not the semantic intent. Never skip() a test that fails due to error-message mismatch; fix the assertion to match the actual Zod output. _(Rationale: 3 newsletter-signup tests were skipped for months because they searched for 'Email is required' when Zod was returning 'Please enter a valid email address' (the .email() validator fires on empty strings before .min(1)). The component was correct; the tests were wrong.)_ — 2026-07-12
- **Convention:** Component deletion recipe: Remove TSX file + CSS module + test file + barrel export line. Verify with npm run build && npm test -- --run. Clean .next cache after deletion to avoid stale route type errors (rm -rf .next). _(Rationale: Each component has 3-4 artifacts scattered across the tree. Missing any one leaves orphan files or stale barrel entries. The .next cache can contain stale route validator types that reference deleted files.)_ — 2026-07-12
- **Architecture:** Use auth.getClaims() for server-side page protection, not auth.getUser(). getClaims() validates JWT signature against published public keys locally (no network round-trip). The returned JwtPayload shape includes sub, email, user*metadata, app_metadata — same fields needed for role checks. Use getUser() only when you need fresh user data from the Auth server (profile updates, email verification check). *(Rationale: Supabase 2026 docs explicitly recommend getClaims() for protecting pages. The migration was surgical: only requireSection() and requireAnyAdmin() in auth.ts changed. Client-side login form keeps getUser() since it needs the full User object right after sign-in. Dashboard layout destructure changed from { user, role } to { claims, role }.)\_ — 2026-07-13
